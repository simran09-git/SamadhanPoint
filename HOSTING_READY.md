# SamadhanPoint — Hosting Ready Guide

## Option A: Docker Compose (recommended for demo)

1. Install Docker Desktop.
2. Open PowerShell in this `sp` folder.
3. Copy `.env.example` to `.env` and set `OPENAI_API_KEY` if you want OpenAI-assisted triage/translation.
4. Run:

```powershell
docker compose up --build
```

5. Open `http://localhost:8080`.

PostgreSQL is created automatically by Docker Compose and the Spring Boot schema initializer creates the application tables.

## Option B: Windows + PostgreSQL

Requirements:
- Java 21+
- Maven 3.9+
- PostgreSQL 16/17/18

Create the database once:

```powershell
& "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres -p 5432 -c "CREATE DATABASE samadhanpoint;"
```

If it already exists, do not recreate it.

Set credentials for the current PowerShell session:

```powershell
$env:DB_URL="jdbc:postgresql://localhost:5432/samadhanpoint"
$env:DB_USER="postgres"
$env:DB_PASSWORD="YOUR_PASSWORD"
$env:OPENAI_API_KEY="YOUR_OPENAI_KEY"
$env:OPENAI_MODEL="gpt-6-luna"
```

Build and run:

```powershell
cd .\backend
mvn clean package -DskipTests
java -jar .\target\samadhanpoint.jar
```

Open `http://localhost:8080`.

## What is server-authoritative

- Complaint language/category/priority are recomputed by Java backend.
- Street-light complaints route to Electrical & Public Lighting.
- Road/pothole complaints route to Roads.
- Department Head scope is Department + Ward.
- Worker scope is Department + Ward.
- Worker assignment is automatic when a matching worker exists; the backend provisions a scoped demo worker if necessary.
- Existing unassigned complaints are repaired on startup/login.
- Citizen Track Status loads the citizen's own complaint codes automatically.
- GPS can be reverse-geocoded to obtain a postcode; the included municipal directory resolves that postcode to the demo ward/zone.
- Complaint location is stored separately from registration location.
- PDF reports are generated by the backend; CSV remains available.

## OpenAI

The OpenAI key is never stored in the source code. Set it as an environment variable. If the key is missing or the API is unavailable, the Java rule engine keeps the demo operational.

## Production hosting notes

Use a managed PostgreSQL service, HTTPS, environment/secrets storage, object storage for large media, and a persistent authentication/session layer before real municipal deployment. The included project is a stakeholder-testable academic MVP.


## Final QA / Known Workflow Rules (2026-10-02)
- Street Light / पथदिवे / streetlight / lamp complaints are routed to **Department of Electrical & Public Lighting**.
- Pothole / damaged-road complaints route to **Department of Roads & Traffic Infrastructure**.
- Routing is recomputed on the Java server from the original complaint text; client category values are not trusted.
- Worker assignment is matched by normalized **Department + Ward** scope. Existing legacy complaints are repaired at startup.
- Citizen Track Status loads the citizen's own tracking codes automatically.
- Citizen Appeals are available in the sidebar and from complaint details after status becomes RESOLVED/COMPLETED/CLOSED. Appeal reason + evidence are stored and sent to Admin/Department Head human review.
- Worker cannot close a complaint directly: worker resolves it; citizen verification closes it.
- GPS reverse geocoding is used when coordinates are supplied; the server derives pincode/ward from the resolved pincode mapping.
- Registration can also capture GPS and auto-fill pincode/ward.
- Supported UI languages are English, Hindi and Marathi.
- OpenAI is assistive; Java routing/security/workflow rules remain authoritative. Responses API endpoint is used when `OPENAI_API_KEY` is configured.


## Final public-hosting sequence (AWS EC2 + Docker)

For an academic/stakeholder demo, the simplest public setup is one EC2 instance running the supplied Docker Compose stack. Put PostgreSQL in the same Docker Compose stack for the demo, and put Nginx/HTTPS in front of the application if the hosting provider/domain setup supports it.

1. Create an Ubuntu EC2 instance (use a current supported Ubuntu LTS image).
2. Allow inbound TCP 22 only from your IP for SSH, and TCP 80/443 for web traffic. Do not expose PostgreSQL port 5432 publicly.
3. Install Docker Engine + Docker Compose plugin.
4. Upload/extract this `sp` project on the server.
5. Create `.env` from `.env.example` and set strong `POSTGRES_PASSWORD`, `DB_PASSWORD`, and `OPENAI_API_KEY` values. Never commit `.env`.
6. Run `docker compose up -d --build`.
7. Check `http://SERVER_IP:8080/api/health` until it reports `HEALTHY` and `database: ONLINE`.
8. Open `http://SERVER_IP:8080` for the demo.
9. For a proper domain deployment, place Nginx/Caddy or the hosting provider's HTTPS proxy in front and expose only 80/443 publicly.
10. After deployment, change/disable demo credentials and create the actual admin/department-head/worker accounts needed for the demonstration.

The application serves the frontend and Spring Boot API from the same origin, so there is no separate frontend hosting step in this package.
