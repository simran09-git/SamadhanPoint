# SamadhanPoint FINAL PRO V7

This release consolidates the final workflow corrections requested for the demo.

## Languages
- UI language choices are limited to English, Hindi and Marathi.
- Server-side language detection stores `detected_language` and `language_confidence`.
- Unsupported language codes are normalized/rejected for managed accounts.

## AI triage
- Complaint routing is server-authoritative: client-supplied category/language is not trusted for final routing.
- Road/pothole signals are weighted strongly so a pothole complaint mentioning rainwater is not routed to Water.
- Category, urgency, duplicate similarity, department and SLA are generated by the local assistive triage layer.

## Ward routing
- Expanded Mumbai demo pincode directory covers many administrative wards and common pincodes.
- Complaint submission requires a supported pincode and derives the ward/zone from the server directory.
- The UI previews the mapped ward and locality before submission.
- Complaint details include a Google Maps search link based on the stored location text; no Google API key is required.

## Department Head RBAC
- Only ADMIN can create/edit/block users and manage departments.
- Department Heads do not get User Management in their navigation.
- A Department Head must be assigned to one specific department + ward; `ALL_WARDS` is rejected for new Department Heads.
- Complaint visibility, appeals, worker assignment and reports for Department Heads are restricted to both department and ward.
- Worker assignment is restricted to the same department + ward.

## Admin / Auditor
- Admin and Auditor complaint registers show ward/location, department, worker, status and detected language.
- Admin and Auditor can filter by language and ward in the complaint register.
- Admin remains the only role with user CRUD and department CRUD.

## Existing workflow retained
- Notifications with unread badge and live polling.
- Appeals after resolution, with reason/evidence and human review.
- Worker before/after evidence upload.
- Citizen verification before closure.
- Department reports and CSV export.
- PostgreSQL + Spring Boot + Docker deployment files retained.
